## 核心架構

- **角色身分**：規格 Owner／Admin／Member；相容層 `boss`→Owner、`employee`→Member。
- **權限原則**：全員工程操作平等；敏感財務、他人薪資、個人隱私另授權。
- **工程可見範圍（DEC-001）**：所有有效團隊成員可查看與操作公司內所有工程。
- **技術**：GitHub + Cloudflare Workers + Supabase + Cloudflare R2；手機優先 PWA。
- **離線**：第一版必要；恢復網路後自動同步。
- **登入（DEC-004）**：Email／密碼為主；LINE 只作操作入口，不作登入憑證。
- **開發策略**：全部主要功能完成並整合測試後，才正式交給團隊使用。

### DEC-005｜Admin 預設權限（已確認）

Admin **預設可以**：
- 核准一般採購
- 核准緊急採購
- 發布與凍結報價

Admin **不得因此自動取得**（須獨立細項授權，與採購／報價 ops 分離）：
- 公司利潤／毛利
- 完整財務資料（`finance.read`／`finance.write`）
- 成本／毛利細項（`finance.cost.read`）
- 供應商應付款總帳
- 他人薪資
- 銀行帳戶敏感欄位
- 門禁與高度敏感資料

### DEC-006｜庫存盤點範圍（已確認）

- Member 依產品決策**可以**調整庫存盤點。
- **本批只完成**：入庫、移動加權平均、負庫存阻擋、基本庫存資料隔離。
- **下一批再做**：盤點調整、盤點差異過帳與相關稽核（本批不自行擴充）。

## 出勤與工地

- 先一鍵上班，再補登工地；切換工地不必重新上下班。
- GPS 僅輔助，不影響一鍵打卡。
- 不自動扣除休息時間。
- 跨日班次（DEC-002）：依實際班次跨日計算，午夜不強制結束。
- 補打卡：員工申請，需確認後生效。
- 請假：員工申請，需確認。
- 出勤異常：每天固定時間彙整至**系統內通知**（不做 LINE 推播）。
- 團隊可見：今日到班狀態、工程參與。
- 個人隱私：打卡明細、更正原因、效率、薪資僅本人／授權者可見。

## 財務與報價可見範圍

**全員可看**：工程報價、報價項目、材料單價、採購金額、工作必要採購明細。

**需授權**：公司利潤／毛利、整體財務、供應商應付款總帳、他人薪資、銀行帳戶敏感欄位。

- 報價稅務（DEC-003 / POL-004）：每張報價建立時選擇含稅／未稅，發布時凍結快照。
- 薪資：每位員工可設月薪／日薪／時薪；每月結算一次；本人可看自己薪資。
- 代墊款：可隨時核銷或月底集中。
- 資金帳戶：銀行與現金分開。
- 零用金：員工可登記自己保管收支；補充需申請後撥款。

## LINE 與通知

- LINE 官方帳號：私訊＋群組；快速按鈕為主。
- 群組照片／文字：辨識後確認再歸檔。
- LINE 六個入口保留：上下班打卡、切換工地、施工回報、材料採購、我的出勤、工程系統。
- 通知管道：系統內通知中心＋待辦為主；另見 DEC-007。

### DEC-007｜LINE 僅回覆、不主動推播（已確認｜覆寫舊「選擇性推播」）

系統**不**對 LINE 做主動推播（採購／報價／出勤／公告皆不 push）。

LINE 官方帳號只作操作入口：
- 使用者主動傳訊或加好友時，由 Edge Function `line-webhook` **回覆**功能選單（六個入口連結）。
- 個人帳號綁定：優先 LINE Login（OAuth）寫入 `profiles.line_user_id`；備援為短時綁定碼。LINE **不作**系統登入憑證（DEC-004）。
- 官方帳號以圖文選單為主入口；webhook 不對一般傳訊回長選單。
- 通知與待辦只寫入系統內（`create_org_notices`）；`safeNotify` 不再 enqueue outbox、不再呼叫 `line-push`。

硬性約束：
- LINE **不作登入憑證**（仍遵守 DEC-004）。
- Webhook／回覆失敗**不可影響**採購／報價／出勤等主交易成功。
- Secrets 僅存 Supabase Edge Function：`LINE_CHANNEL_ACCESS_TOKEN`、`LINE_CHANNEL_SECRET`。

## 施工、品質、維修

- 工程類型：正式工程＋臨時維修；維修可獨立建立並可關聯原工程。
- 照片：自動整理＋員工確認；保留原圖＋壓縮瀏覽圖；永久保存；主要雲端＋獨立自動備份。
- 施工日誌：自動彙整草稿，團隊確認後發布；暫不對客匯出。
- 隱蔽工程：員工完成檢查表即可確認。
- 缺失：快速新增；小型團隊一般缺失允許本人複驗；安全／正式要求仍依規範。
- 改善→複驗→手動結案同一頁連續完成，三筆紀錄獨立保存。
- 結案後照片僅作補充證據。
- 客訴：員工可自行處理結案；重大客訴由員工主動通知老闆；結案後不要求複查。
- 維修完成：優先取得客戶確認；不主動售後追蹤。
- 保固：到期前提醒（系統內通知）。

## 待辦與效率

- 首頁：今日待辦＋功能宮格；快捷可自訂。
- 待辦排序：系統預設，可自行切換。
- 延期：可自行調整截止時間，每次必填原因。
- 跨工程待辦：員工可在有權限工程自行新增。
- 待辦修改：負責人及老闆可改；同工程授權員工可直接協作。
- 協作回報直接生效；一般更正免填原因，重要更正才必填。
- 效率報表：標準版；員工可看完整個人報表；老闆可看具名比較。
- 不填預估工時；負荷只顯示待辦數量。
