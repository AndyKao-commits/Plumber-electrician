三、發現事項與修正建議
REV-01｜P0｜DOC-03／DOC-06
發現：報價資料可參照獨立維修，但 FIN-001 只依賴 FIELD-001；正式建立 quotations 的 repair_case_id 外鍵前須有 repair_cases。
修正：將 FIN-001 拆成不依賴案件的模板／草稿基礎與依賴 REP-001 的正式報價關聯，或將 CRM/REP 主檔提前；同步修正 Migration 相依。
REV-02｜P0｜DOC-03
發現：Migration 011 為 RLS 最終補強，雖註明逐批建立最低安全策略，仍缺每批上線安全門檻。
修正：每批含租戶資料表均須同批建立 RLS、同組織外鍵、預設拒絕及隔離測試；011 僅效能與總複核。
REV-03｜P1｜DOC-01／02／03／06
發現：POL-004 確認每次建立報價時選稅務，但 API 與工作票偏重「發布前」驗證，資料庫欄位可能允許草稿空值。
修正：正式 POST /quotations 即要求 tax_mode；如另有空白範本，應用不同資源類型，不得將未選稅模式草稿視為正式報價。
REV-04｜P0｜DOC-02／03／06
發現：緊急採購每日額度未完整定義取消、修改、部分取消、退款與跨日事件的占額釋放方式。
修正：新增 immutable emergency_limit_events／reservation 狀態，明定原始業務日、取消授權與併行鎖定；退款不得自動回補原日額度。
REV-05｜P0｜DOC-03／06
發現：零用金工作票有申請、核准、撥款，但資料字典／API 缺乏完整補充、餘額、憑證及核對模型。
修正：補 petty_cash_accounts、top_up_requests、disbursements、ledger_entries、reconciliations 與權限／測試對照。
REV-06｜P1｜DOC-03／05
發現：移動加權平均有正向入庫案例，但退貨、零庫存、成本調整、不同庫位與歷史成本重算規則不完整。
修正：指定成本池層級（建議組織＋材料）、成本調整沖銷事件與四捨五入精度；補測試。
REV-07｜P1｜DOC-04／06
發現：採購申請人是否可自我核准、管理者財務預設權限尚未決策；會影響工作票完成條件。
修正：在 AUTH-003／PUR-001 前設政策決策門檻；未決前預設禁止自我核准及敏感存取，待 Owner 核准。
REV-08｜P1｜DOC-05／06
發現：文件前述「75 項測試」與實際列舉數量未嚴格對齊；工作票引用部分不存在或未精確映射的案例編號。
修正：以機器可核對的唯一案例 ID 清冊重算；目前 DOC-05 可辨識 68 個非 E2E 案例及 8 個 E2E 流程，共 76 條（依本次抽取規則）；逐票校驗引用。
REV-09｜P1｜DOC-01／03／04
發現：客戶資料保留期限、門禁秘密銷毀、附件權限撤銷及匯出審批未決。
修正：補資料分類、保留與刪除策略、稽核例外與私有連結過期測試；政策核准前禁止正式資料匯出。
REV-10｜P0｜DOC-05／07
發現：RPO/RTO 目標已確認，但未有可驗證的供應商能力、資料庫＋附件一致性恢復與費用方案。
修正：DEV-007 先完成技術可行性及成本評估，REL-003 以隔離環境實際演練；未達標阻擋正式發布。
REV-11｜P1｜DOC-02／03
發現：預收、折讓、退款與供應商信用額度存在重複計算風險，尚缺逐事件會計式核對表。
修正：補不可變財務事件、單據分配上限、退款可退餘額及雙重扣減防護測試。
REV-12｜P1｜DOC-01／05／06
發現：E2E-01 工程順序與部分工作票順序不同，且修繕與工程報價的資料先後需明確。
修正：E2E 流程以事件合法前置為準，不強迫工程先施工後報價；允許報價先於施工，驗收涵蓋兩種情境。
四、開發工作票與測試盤點
DOC-06 可辨識 47 張唯一工作票（與文件宣告一致）。DOC-05 表格可辨識 68 個一般測試案例，另有 8 個 E2E 流程；本次統計合計 76 條。正式封版時須明定是否將 E2E 納入總數，並以機器可驗證的測試清冊為唯一來源。
