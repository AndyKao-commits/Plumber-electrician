# 水電工程管理系統｜最終整合開發規格（待授權版摘要）

重建自規劃對話最終整合結果。非正式 Word 原文。

## 系統定位

手機優先 PWA「工程管家」：出勤、工地／工程、施工回報、材料採購／庫存、報價、維修保固、零用金、系統內通知待辦、會計匯出。  
LINE 官方帳號僅作操作入口；**全面停用系統主動 LINE 推播**。

## 已確認五項政策（不可改回）

| 編號 | 政策 | 規則 |
|---|---|---|
| POL-001 | 一般採購核准基準 | 折扣後含稅運之最終應付金額 ≥ NT$3,000 需事前核准 |
| POL-002 | 緊急採購每日上限 | 每人每日 NT$10,000（Asia/Taipei）；單次 ≤ NT$5,000 |
| POL-003 | 一般材料成本 | 移動加權平均 |
| POL-004 | 報價稅務 | 每次建立報價時選擇；發布凍結快照 |
| POL-005 | 備份復原 | RPO 1 小時／RTO 4 小時 |

## 權限總則

- 有效組織成員：全員工程操作平等（查看／操作所有工程）
- 敏感財務（毛利、整體財務）、他人薪資、個人打卡明細／效率：需額外授權
- 採購達門檻核准、財務收付款、成員管理、備份管理：額外授權
- 角色標籤（老闆／員工）不是一般工程功能的唯一資格

## 出勤

- 先一鍵上班，再補登／切換工地
- GPS 輔助、不擋打卡；不自動扣休息
- 跨日班次：午夜不強制結束
- 團隊可見今日到班與工程參與；明細隱私

## 採購／庫存／零用金

- 最終應付金額公式：商品 − 折扣 + 稅 + 運費 + 其他買方費用
- 緊急額度需不可變占用／釋放事件（DOC-09）
- 混合庫存；重要材料逐筆；小耗材簡化
- 零用金：申請 → 核准 → 撥款 → 流水帳（DOC-09 補齊）

## 報價／財務

- 報價可關聯工程或獨立維修（明確外鍵，二擇一）
- 合約金額僅計已接受版本與已接受追加減
- 請款、收款、收入分開建模

## 維修／保固／品質

- 維修可獨立建立並可關聯原工程
- 小型團隊：一般缺失可本人複驗；安全／正式要求仍依規範
- 保固到期：系統內通知（非 LINE 推播）

## 通知

- 僅系統內通知中心＋待辦
- 通知「已讀」≠ 業務「已完成」

## 技術方向

- 前端：Vite／React／PWA／TanStack Query（本 repo 已採）
- 後端資料：Supabase（PostgreSQL + Auth + Storage）
- 部署：Cloudflare（Workers／Pages）＋ R2（視需求）
- 登入：Email／密碼為主；LINE 不作登入憑證
- 組織隔離：`organization_id` + RLS 每批同步

## 開發策略

全部主要功能完成並整合測試後，才正式交給團隊使用。  
正式開工需專案負責人明確授權。

## 尚未擅自定案

- 採購人是否可核准自己的採購
- 人工成本、收入認列、保固起算細部、稅務細節等可設定項
