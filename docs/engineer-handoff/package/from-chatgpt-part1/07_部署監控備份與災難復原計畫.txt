01｜目的、範圍與責任
確保工程、客戶、維修、材料、採購、零用金、報價與收付款資料，在版本發布、服務中斷、誤刪及災害情境下可安全維護與復原。維運涵蓋應用程式、PostgreSQL、物件儲存、身分驗證、排程工作、金鑰與審計證據。

03｜備份政策：RPO／RTO
指標
已核准目標
驗證方式
RPO
≤1 小時
以故障時間與最後可還原且一致的資料點比較
RTO
≤4 小時
從宣告災難至核心服務及資料核對恢復可用
資料範圍
DB、照片、PDF、必要設定與密鑰恢復程序
抽樣還原與附件一致性比對
演練頻率
建議每季一次，重大變更後追加
保留時間戳、步驟、耗時、結果與簽核
備份頻率與保留天數需依實際方案與費用決定。只有每日完整備份通常無法單獨保證 1 小時 RPO；可能需要 PITR／WAL 或等效連續備份。DB PITR 不會自動保證 Storage 物件同步還原，須另設物件版本化、異地複本或可驗證的增量備份。
備份安全要求
備份應加密、限制存取、隔離正式服務帳號並保留操作稽核；備份金鑰及恢復憑證不可與唯一一份備份放在同一故障域。刪除與保留期限應遵守資料保護需求。建議定期抽驗備份可讀性及完整性，而非只檢查工作是否顯示成功。
04｜災難分類與復原順序
等級
範例
初步處置
SEV-1
跨組織資料外洩、財務錯帳、不可用且影響所有人
停止危險寫入、保全證據、立即通知 Owner
SEV-2
主要功能中斷、照片大量無法存取
暫停相關流程、切換降級模式、啟動修復
SEV-3
局部頁面異常、少量重試失敗
建立事件單、評估修復及下一版本
建議復原優先順序：①身分與組織隔離 ②核心資料庫一致性 ③庫存與採購交易 ④收款與帳款 ⑤工程／維修資料 ⑥照片與 PDF ⑦統計與非核心功能。若財務或庫存一致性無法證明，相關寫入功能應維持唯讀或暫停。
復原演練操作契約
A. 宣告事件與紀錄 T0；B. 凍結危險寫入、保留故障證據；C. 選定一致的資料庫復原點；D. 在隔離環境還原 DB、物件及必要設定；E. 驗證組織隔離、資料筆數、庫存帳、應收應付、照片連結；F. 切換服務與 DNS／流量；G. 恢復寫入前完成 Owner 確認；H. 記錄最後可用交易時間及 T_restore，計算實測 RPO／RTO。
05｜資料庫 Migration 與回滾
Migration 以版本化、可重複驗證與向後相容為原則。先新增欄位或表，再發布支援新舊結構的程式，完成資料回填及驗證後，才於後續版本移除舊結構。禁止未備份就直接執行不可逆刪除或欄位重命名。
變更類型
回滾策略
純應用程式更新
重新指向上一個經驗證版本；驗證資料相容
可逆結構變更
執行經測試的逆向 Migration 或前向修復
不可逆資料變更
先建立還原點與資料快照；採受控前向修復或完整還原
金流／庫存已產生新交易
禁止直接回復舊 DB 導致交易遺失；須制定交易對帳及補登方案

07｜資料安全、憑證與權限撤銷
正式密鑰放在受控環境變數或秘密管理服務；前端不得取得 Service Role。定期輪替憑證並演練洩漏撤銷；離職或停用成員應立即失去敏感 API 與檔案存取。簽名網址短效、匯出受權限管控。事故證據應限制閱覽並保留處置紀錄。
