2. 共用欄位、索引與資料治理
所有組織業務表原則包含 id UUID PRIMARY KEY、organization_id UUID NOT NULL、created_at/updated_at TIMESTAMPTZ、version INTEGER NOT NULL DEFAULT 1。事件流水帳可採不可變事件時間欄位，不必機械套用 updated_at。
跨表關聯須驗證相同 organization_id；建議使用 UNIQUE(organization_id,id) 配合複合外鍵，並建立對應索引。
所有正式帳務、庫存、稽核與已發布快照採 append-only；修正用 reversal / compensating entry，不能 UPDATE 原始過帳金額。
刪除採分級政策：一般草稿可軟刪；已過帳資料不可硬刪；個資刪除須遵循保存與匿名化政策，不能破壞稽核。
重要唯一鍵：組織內單號、邀請有效 token 雜湊、冪等鍵作用域、同一正式事件來源識別碼。

5. 必須以資料庫保障的不變條件
報價目標 XOR：CHECK ((project_id IS NOT NULL) <> (repair_case_id IS NOT NULL))；兩端同組織。
正式庫存可用量 = 現有量 − 有效預留量；交易鎖定相關餘額行；不得產生負可用量或負實存。
採購金額 final_payable = 折扣後商品金額 + 稅 + 運費 + 其他應付費用；已核准金額變動後必須重新評估。
緊急額度使用單一交易內的員工日額度占用表或可鎖定彙總行，防止兩筆同時通過。
收款分配合計 ≤ 已確認可分配收款；退款、預收款抵充及折讓各自保留獨立來源。
正式發布的報價、已確認的庫存流水、金流、稽核事件不得覆寫；用版本或反向事件修正。
缺失、保固、客訴與維修結案均需按狀態機檢查，P0 安全問題不得直接一般結案。

8. RLS 與敏感資料策略
資料庫 RLS 以 active organization_members 與細項 permission_grants 判斷；前端權限僅作體驗，不是安全邊界。
對財務、薪資、門禁資訊採最小權限；必要時用獨立表、受控視圖或服務端查詢避免欄位外洩。
Storage 私有檔案以組織與資源授權產生短效連結；移除 EXIF 位置資訊再公開匯出。
Service Role 僅後端使用；每個管理操作仍需驗證呼叫者權限並留下稽核。
跨組織外鍵、查詢與匯出均需測試；對無權資源避免暴露存在性。
9. 索引、效能與維護
常用索引：organization_id + status + created_at；organization_id + project_id；organization_id + customer_id；organization_id + business_date。
流水帳索引：organization_id + material_id + posted_at；organization_id + source_type + source_id（唯一）；金流來源及分配索引。
照片檔案與資料列分離；資料庫保存 Storage 路徑、雜湊、媒體類型、權限與引用關係。
備份需包含資料庫、私有檔案與設定；RPO 1h／RTO 4h 必須在實際選定的服務方案做復原演練。

11. 待決政策與實作前檢查
人工成本計算、會計收入認列、保固期間與排除條款、供應商結帳日、稅額進位規則，保留組織／契約層級設定，不自行假設。
須先確定資料刪除保留政策、資料庫高精度 NUMERIC 規模、是否跨幣別及稅務發票資料欄位。
正式 DDL 應另附每表完整 CREATE TABLE、外鍵、CHECK、索引、RLS policy、回滾方案與 migration 測試；本文件是設計契約，不冒充完整 SQL。
