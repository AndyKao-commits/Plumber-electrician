1. 範圍與規格優先序
適用 /api/v1 的組織、工程、出勤、材料、採購、報價、財務、客戶、維修及同步 API。
已核准政策優先於建議預設；未核准項目必須維持可配置或阻擋正式發布。
所有業務資料均須驗證 organization_id 與當前授權組織；前端送來的組織 ID 不視為授權證明。
財務、庫存、核准、正式發布與結案操作必須記錄必要稽核事件。

10. 交易、冪等與並行處理
冪等唯一鍵範圍至少包含 organization_id、actor_id、operation_type、idempotency_key；同鍵不同 request_hash → 409。
緊急採購的每日占額以 Asia/Taipei 日期、員工及組織為單位；同一交易鎖定額度並建立採購承諾。
庫存調撥與耗用必須在同一交易更新流水帳及餘額；禁止負庫存，失敗全部回滾。
收款分配、預收抵充與退款應鎖定相關餘額，確保不可超額；只記一次實際現金流。
報價發布、接受、追加減接受及正式請款採不可變版本或補償紀錄，不直接改寫歷史。
外部上傳與資料庫交易不能天然原子化；採用 pending→verified→linked 的受控狀態與清理工作。
